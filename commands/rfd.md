# /rfd — RFD（提案・論点出し）の起票

引数: $ARGUMENTS（テーマ: 解きたい課題や要望を1文で）

## 実行内容

dev-lifecycle スキルの工程0。**実装方針を決める前に、選択肢を並べて人間の決定を取る**フェーズ。

1. **課題を事実で書く**
   - 今何が起きていて、放置すると何が困るかを、推測でなく観測できる事実で記述する
   - 影響範囲（対象ユーザー・システム・ファイル）と、触らない範囲を明示する
2. **選択肢を2つ以上出す**
   - 「何もしない」を必ず選択肢に含める
   - 各案に 利点 / 欠点 / コスト（工数・運用） を並記する。1案だけ提示しない
3. **推奨を1つ示す**（判断軸＋比較の形式。決定はしない）
4. **`docs/lifecycle/00-rfd.md` に `RFD-xxx` として追記する**
   - 雛形が無ければ `./scripts/init-lifecycle.sh .` を先に実行する
   - ID は見出し行の先頭に置く（`### RFD-003 ...`）
5. **決定は人間に求めて停止する**
   - 承認を得たら「決定」「却下理由」「スコープ外」を追記し、後戻りが高い判断は ADR（`templates/ADR-template.md`）を起こす

**AI は RFD を承認しない。** 決定欄が空のまま要件定義へ進んではいけない。

出口基準の詳細: `skills/dev-lifecycle/references/phase-gates.md`
