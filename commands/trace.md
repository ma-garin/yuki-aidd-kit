# /trace — トレーサビリティの更新と検証

引数: $ARGUMENTS（任意: 対象ディレクトリ。既定は `docs/lifecycle`）

## 実行内容

要件が設計・実装・テストへ紐づいているかを、目視でなくスクリプトで判定する。

1. **`./scripts/trace-check.sh <対象ディレクトリ>` を実行する**
   - 検出: 重複定義 / 未定義参照 / 所有ファイル違反 / 追跡表に未記載 / カバー漏れ / 孤立テスト
   - 全件は `trace-check-report.md` に書き出される。**会話には結論（NG件数）と根拠（種別ごとの件数・先頭5件）だけを出す**
2. **NG を分類して原因に応じて直す**
   - 追跡表に未記載・カバー漏れ → `traceability-matrix.md` を更新する（空欄は禁止。非該当は `-`）
   - 未定義参照 → 採番ミスか、存在しない要件の実装。**要件側を疑う**（勝手に要件を追加しない）
   - 重複定義・所有ファイル違反 → 工程文書に対応表を複製している。追跡表へ一本化する
   - 孤立テスト → 検証対象の要件が不明なテスト。要件に紐づけるか削除する
3. **NG=0 になるまで繰り返し、最後に結果を報告する**

## 注意

- **追跡表を埋めるために要件・テストを新規に発明しない。** カバー漏れは「その工程が未実施」というシグナルなので、埋めずに該当工程へ差し戻すのが正しい対処のことがある
- ID 体系と検査内容の詳細: `skills/dev-lifecycle/references/traceability.md`
