# /e2e-cycle — 段階停止型 E2E テスト＆不具合修整ワークフロー

引数: フェーズ番号 `1`〜`5`、または `help`。省略時は成果物の有無から次フェーズを自動判定する。

## 実行内容

- `help` の場合: 下の「使い方」をそのまま本文で表示して終了する。ツール実行・ファイル操作・フェーズの起動は一切しない。
- それ以外: `skills/e2e-cycle/SKILL.md` に従い、**指定された 1 フェーズだけ**を実行し、「ステップN完了」と報告して必ず停止する。`sleep`・ポーリング・バックグラウンド実行は禁止。

## 使い方

E2E テストを「設計 → スクリプト生成 → 実行 → 修整 → コミット」の 5 フェーズに分割し、1 回の起動で 1 フェーズだけ実行して必ず停止する。

| コマンド | 動作 |
|---|---|
| `/e2e-cycle` | 成果物の有無から次フェーズを自動判定して 1 フェーズ実行 |
| `/e2e-cycle 1` | テスト設計: コード把握 → ロール/ペルソナ別ユースケース → `docs/system_test_cases.csv`（ツアー観点・severity 付き） |
| `/e2e-cycle 2` | 準備: CSV を元に Playwright スクリプトと設定を生成（実行はしない） |
| `/e2e-cycle 3` | 実行: フォアグラウンド 1 回でテスト実行、Pass/Fail/Skip 件数を報告 |
| `/e2e-cycle 4` | 修整: Fail を ODC 分析し、製品欠陥/テスト陳腐化/環境依存/flaky を判定。不具合 1〜2 個を修整 → 対象のみ再テスト → 停止 |
| `/e2e-cycle 5` | 完了: ドキュメント同期と Git コミット（artifacts 等の除外を確認） |

典型的な流れ: `1` → CSV をレビュー → `2` → `3` → `4` を Fail が解消するまで繰り返し → `5`。
各フェーズは完了すると必ず停止する。次のフェーズは自分で起動する。自動判定が怪しいとき（スクリプト修整後の再実行など）は番号を明示する。
テスト戦略・ゲート基準は `skills/test-strategy`、完了判定は `done-gate`。
