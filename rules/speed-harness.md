# 開発速度ハーネス（H-1〜H-8）
所要時間 ≒ 往復回数 × 12秒。速度は「工程を削る」でなく「往復を削る」で作る。ゲート（pre-commit / verify-ui / 破壊操作の確認）は削らない。
モデル・effort・委譲の採算は `rules/model-routing.md`。各 H の出所となった実測・失敗事例と、H-6 の実測記録: `internal/rules-rationale/speed-harness.md`（毎回は読まない）。
## H-1. 着手前4行（必須出力。最初のツール実行より前）
```
目的: <1行>
終了条件: <何が満たされたら止まるか。ゲート名・ファイル・件数で。曖昧な着手を防ぐ>
見積: 自分 n 往復 + 委譲 m 本 × 上限 k 回（≒ X 分）
検証: <何を・何周で確認するか。既定は1周>
```
## H-2. 環境チートシート（その場で探索せず、ここからコピーする）
プロジェクトごとに埋める。作業中に探索した項目は終了時にここへ追記する。
```bash
<起動コマンド>                                                                 # 検証用: 認証オフ・ブラウザ自動オープンなし
curl -s --retry 15 --retry-delay 1 --retry-connrefused -o /dev/null -w "%{http_code}" http://127.0.0.1:<PORT>/   # 待機ループを組まない
kill $(lsof -ti:<PORT>) 2>/dev/null                                            # pkill -f は効かないことがある。ポートで殺す
```
- 編集の反映条件（再起動が要るか / ホットリロードか）: <記入>　／　認証・外部通信を止める手段: <記入>
- 既知の不具合・触ってはいけないファイル: <記入>　／　スクショは scratchpad の絶対パスを最初から `filename` に指定

| 場面 | 標準 |
|---|---|
| 一時ファイルの片付け | `mv <対象> <scratchpad>/`（削除でなく退避） |
| コミット対象 | パスを明示して `git add <path...>`（`git add -A` 禁止） |
| PR の作成とマージ | 別々のコマンドとして順に実行（連結すると Base branch was modified で失敗） |
| 複数ファイルの編集 | Read 全件1メッセージ → Edit 全件1メッセージの2往復に固定 |

安全フックに止められたら、安全装置が正しく働いた結果として受け入れ、標準コマンドに切り替える。
## H-3. UI 作業の型（バッチ検証）
編集を全ファイル分まとめる → 再起動1回 → 対象画面のスクショを連続で全部 → まとめて読む。直しが出たら「全修正 → 1回検証」をもう1周、**上限2周**。3周目が要る状態は設計不良。手を止めて報告する。
## H-4. 委譲
自分の往復5回以内なら自分でやる（委譲の固定費 60〜90秒/本）。超える場合の採算判断は `rules/model-routing.md`。委譲プロンプトには **H-2 相当の確定情報・「再調査禁止」・書き出し先と10行以内の要約・出力フォーマット** を必ず同梱し、1本ごとにツール回数上限を明示する（既定20回）。**作った本人に検証させない**: 検証系を1本以上含め、指示は「合っているか」でなく「壊れている箇所を探せ」、直列90秒を見積に足す。
## H-5. 見積の既定に含めるもの（実測から）

| 項目 | 既定 |
|---|---|
| 検証後の修正パス | +1〜2分 |
| 実行系の実証を含む作業 | 1実行の実測時間 × 周回数を先に足す |
| 共有ファイル（複数画面から参照される資産）への変更 | +15分（回帰洗い出し1本 + 検証1本 + 修正パス） |
| 検証の既定 | 代表画面のサンプリング。残りは「未検証」と明記 |
## H-6. 違反時
見積の1.5倍を超えたら、原因1行を `internal/rules-rationale/speed-harness.md` の実測記録に追記してから完了報告する。ルールを新設せず、H-1〜H-5 のどこで落ちたかを特定する。
## H-7. コミット・プッシュ・マージ
- ゲート（pytest / make test / verify-ui / lint）は**ユーザーが要求した時だけ実行する**（Claude Code では `block-gates.py` が強制。要求時は `GATES_REQUESTED=1` を付ける）
- 実行したときの出力は `filter-output.py` が失敗行＋集計に絞る（全量は `FULL_OUTPUT=1`）。絞られた結果で判断できないときだけ全量を取る
- 手順は一直線: add（パス明示）→ commit → push → PR 作成 → マージ。作成とマージは別コマンド
- コミット前に変更の性質（docs のみ / code / UI）を1行で確定させる
- ゲートが赤なら: 変更を stash した素の状態で同じ失敗が再現したら main 由来と断定し、それ以上切り分けない。PR 本文に「main 由来・スコープ外」と1行
## H-8. 進捗の逐次提示
- 1分超の作業は開始時に見積を宣言し、同じ bash に `python3 <hooks>/progress.py start "<タスク名>" <見積秒>` を連結する
- ステップ境界で `progress.py step "<n/m 名称>"` を既存コマンドへ連結する（専用の往復を作らない）
- ツール実行の合間の本文は `[2/5 配線] 経過 1:20 / 見積 4:00・残り 2:40` の1行から始める
- **完了時に必ず `progress.py done`**（消し忘れは偽の「実行中」表示になる）
