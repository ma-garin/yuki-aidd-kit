# 原本の配置と網羅性

全件参照の真実源は checkout 自身。ファイル本文をここへ複製せず、追加・変更・削除は台帳で把握する。

| 場所 | 原本の役割 |
|---|---|
| 00_導入 | 導入・配布・初期化・検査 |
| 01_利用者向け資料 | ガイド・操作例・資産案内 |
| 02_共通 | rules・雛形・共通ツール |
| 03_ClaudeCode | スキル・コマンド・agents |
| 04_Codex | Codex生成器・固有資産 |
| 05_プロジェクト管理 | 要求・構想・構成管理 |
| 06_保守者向け | 内部仕様・根拠・回帰 |
| INDEX.md等ルート | 全体地図・版・導入案内 |

`03_ClaudeCode/hooks/` は実装として参照し、Codex で自動実行されるとは解釈しない。
`04_Codex/skills/` は生成結果。元スキルに付属する references・scripts も生成対象であり、本文だけの移植で済ませない。
`05_プロジェクト管理/` と `06_保守者向け/` は既存配布方針に従いプロジェクトへ無断で配らない。
バイナリは全バイト読込とハッシュで識別し、視覚確認等を行っていなければ内容検証済みとはしない。

## 全件確認の手順

1. `kit_catalog.py --root <kit> inventory --output <台帳.json>` を実行する。
2. 全件の status を集計し、秘密情報、参照外、読取不能、バイナリを別に数える。
3. スキル・規約・設計・道具は原本を読む。大量 CSV 等も原本への参照を残し、集計と精読を区別する。
4. 読んだパス・行範囲と判断への影響を作業証拠へ記録する。未精読を省略して「全件精読」と報告しない。
5. 原本・生成物・manifest と、導入先で実際に使うスキルを照合する。

この仕組みは一度に全原文をモデルへ投入する必要を減らす。省略を禁じられた資料は全範囲を読み、
コンテキスト上限を超える場合も、読んでいない範囲を明示し、台帳や要約だけで精読済みにしない。
