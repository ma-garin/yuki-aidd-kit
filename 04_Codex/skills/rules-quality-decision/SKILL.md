# 品質判断（何を守り、いつ止め、いつ戻すか）

成功件数で判断しない。最初に決めるのは指標ではなく「守るもの」と「許容できない失敗」（出所: 作者 note 連載「AI駆動開発(AIDD) x QAメモ」）。記入は `02_共通/ひな形/品質判断カード.md`、出力は `/quality-card`。

## 品質制御ループ（6 段階）

| 段階 | 決めること |
|---|---|
| ① 目的・品質要求 | 誰が何をできればよく、何ができてはいけないか |
| ② リスク・制御 | 失敗の仕方・防ぐ手段・検知する手段 |
| ③ 指標・証跡 | 何を数え、どこに残すか |
| ④ 監視・判定基準 | いつ・誰が・どの基準で見るか |
| ⑤ 判断・対応 | 進める／止める／戻す／誰に判断を求めるか |
| ⑥ フィードバック | 見逃しを要求・制御・評価方法へ戻す |

## 停止条件と再開条件は対で書く

- 停止の例: 他の利用者の履歴が見える状態が 1 件でも確認されたら先へ進めない
- 再開の例: 修正版で同じ要求の確認セットを通し直した証跡があり、提供する版が確認した版と一致している
- 停止条件だけ書いて再開条件が無いものは未完成

## 保留条件

次のいずれかで保留する。成功件数だけでリリース可と判断しない。
1. 要求違反がある
2. 未実行の条件がある
3. 確認した版と届ける版が一致しない

## AI の報告を受けたら 3 つ聞く

1. 成功件数の前に、何を守るためのテストか
2. どの要求を、どの版で確かめたか
3. 未確認の範囲は何か

## 確認の厚さと優先順位

- 厚さは「失敗時の損失・失敗の見つけにくさ・取り消しやすさ」で決める
- 優先順位は発生確率×影響の掛け算だけで決めない。「誰に何が起きるか・提供前に見つけられるか・起きた後に取り消せるか」を並べる

## 自律レベルと止め方

段階が上がるほど止め方を強くする。

| レベル | 止め方 |
|---|---|
| L0 手動 | — |
| L1 補完／L2 対話支援 | 取り込みを止める |
| L3 コーディングエージェント | 範囲と権限を絞る |
| L4 複数エージェント | 統合結果の検証者を決める |
| L5 本番運用 | 取り消せない操作の前に人の承認。作業そのものを止めて人の運転に戻す |

## 指示と制御の使い分け

- 情報漏えい・取り消しにくい操作は「制御」（hook・CI）。AI の判断と無関係に止まる
- 書き方や設計の好みは「指示」（CLAUDE.md）
- 制御の中に AI の判定を組み込んだ部分は指示と同じく揺れる。複数回実行の対象にする
- hook の時間切れ・想定外エラーは素通りしうる。「止まらなかった」と「合格した」を区別し、確認が動かなかったときは止める側に倒す
