# AI 開発の準備度（agent-ready）

AI が**初見で**、起動でき、変更を検証でき、文書を信じて作業できるかを測る。直すのは利用者（または別の作業）で、この採点では対象を変更しない。

## 3 観点（それぞれ別のサブエージェント）

| 観点 | 問い | 詳細 |
|---|---|---|
| 立ち上がり | 何も知らない AI が、手順どおりに起動までたどり着けるか | [references/checks.md](references/checks.md) §A |
| 検証ループ | 変更後に「正しいか」を 1 コマンドで機械が判定できるか | §B |
| 文書の信頼性 | README・AGENTS.md/CLAUDE.md の記述は実物と合っているか | §C |

観点ごとに**独立したサブエージェント**に依頼する（並列）。他の観点の結果を渡さない（先入観を避ける）。依頼文は references/checks.md の「依頼文の型」を使う。

## 配点

各観点 100 点。観点の合計は 3 観点の平均。

| 区分 | 比重 | 中身 |
|---|---|---|
| 決定的な検査 | **70%** | ファイルの有無、コマンドの存在、実行の成否と終了コード、記述と実物の突合。同じ対象なら誰がやっても同じ結果 |
| 挙動の判断 | **30%** | 手順を読んで実際にたどれるか、エラー文が次の行動を示すか、構成が追いやすいか。サブエージェントの判断（根拠を 1 行付ける） |

決定的な検査の各項目は 0/1（部分点なし）。挙動は 0〜4 の 5 段階で、根拠の無い高得点は付けない。

## 手順

1. 対象のパスを確定。リポジトリでなければ止まる
2. 3 サブエージェントを並列に起動（読み取り専用。**書込み・install・外部送信をさせない**）
3. 決定的検査の実行は、対象で**既に定義されているコマンド**だけ（`package.json` の scripts、Makefile、README に書かれたテストコマンド）。時間がかかるもの・副作用があるもの（本番接続・削除・デプロイ）は実行せず「未実行」と書く
4. 結果を統合し、表 1 つで返す

## 出力の型

| 観点 | 点 | 最大の欠点 | 直す順 |
|---|---|---|---|
| 立ち上がり | /100（決定 x / 挙動 y） | | 1 |
| 検証ループ | | | 2 |
| 文書の信頼性 | | | 3 |
| **総合** | | | |

続けて「直す順」の上位 3 件を、各 1 行（何を・どのファイルに・直ったかを確かめるコマンド）で書く。実行しなかった検査は「未実行：理由」を表の下に並べる。

## 守ること

- 採点は**実測と実物の突合**で行う。「ありそう」で加点しない
- 対象の秘密情報（`.env` の値など）を読まない・出力に載せない
- 点数を上げるために対象を書き換えない。改善が必要なら提案だけ返す

## 適用範囲と引き継ぎ

**使わない場面**: キット自身の検査（`06_保守者向け/` の検査群）、アプリの品質レビュー（`qa-review-standards`）、セキュリティ点検（`security-audit`）。
**次に渡す先**: 直す作業は `/plan` から。検証ループの設計は `test-strategy`、文書の整備は該当プロジェクトの AGENTS.md/CLAUDE.md。
