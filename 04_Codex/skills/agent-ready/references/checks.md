# agent-ready 検査項目

各項目は「決定」（機械で白黒が付く）か「挙動」（判断）。決定は 0/1、挙動は 0〜4。

## §A 立ち上がり

| # | 区分 | 項目 |
|---|---|---|
| A1 | 決定 | README かそれに準ずる文書に、セットアップ手順の節がある |
| A2 | 決定 | 依存関係の宣言ファイルがある（`package.json` / `pyproject.toml` / `requirements.txt` / `go.mod` など） |
| A3 | 決定 | ランタイムのバージョンが固定・明記されている（`.nvmrc` / `.python-version` / `engines` / README） |
| A4 | 決定 | 起動コマンドが 1 つに定まる（scripts・Makefile・README のいずれかに明記） |
| A5 | 決定 | 必要な環境変数の一覧がある（`.env.example` など）。実値はリポジトリに無い |
| A6 | 決定 | 起動に人間の対話入力（ブラウザ認証・手動の GUI 操作）を必要としない手順が示されている |
| A7 | 挙動 | 手順を上から実行して、迷わず起動まで着けそうか（欠けている前提の指摘） |
| A8 | 挙動 | 起動失敗時のエラー文が、次の行動を示すか |

## §B 検証ループ

| # | 区分 | 項目 |
|---|---|---|
| B1 | 決定 | テストコマンドが 1 つに定まる |
| B2 | 決定 | テストを実際に実行でき、終了コードで成否が分かる（実行した場合のみ。未実行なら 0 ではなく「未実行」） |
| B3 | 決定 | テストファイルが存在し、件数が 1 以上 |
| B4 | 決定 | lint または型検査のコマンドがある |
| B5 | 決定 | 結果の末尾 1 行に件数・成否が出る（`N passed` 等）か、機械可読な出力（JSON/JUnit）がある |
| B6 | 決定 | 変更前後の差分から対象テストを絞れる、またはテスト全体が数分以内に終わると明記されている |
| B7 | 挙動 | テストが実際に仕様（受入条件）を検証しているか。件数だけの飾りでないか（2〜3 件を抜き読み） |
| B8 | 挙動 | 失敗時の出力から原因箇所に到達できるか |

## §C 文書の信頼性

| # | 区分 | 項目 |
|---|---|---|
| C1 | 決定 | AI 向けの指示ファイルがある（`AGENTS.md` / `CLAUDE.md` / `.cursor/rules` など） |
| C2 | 決定 | 文書内のコマンドに出てくる scripts 名・Make ターゲットが実在する（突合して欠落ゼロ） |
| C3 | 決定 | 文書内のパス（ファイル・ディレクトリ）が実在する（欠落ゼロ） |
| C4 | 決定 | 文書内の内部リンクが切れていない |
| C5 | 決定 | 指示ファイルが長すぎない（目安: 300 行以内）。長い場合は分割・参照になっている |
| C6 | 決定 | 文書と依存宣言のバージョンが矛盾しない（README の Node/Python の版と宣言ファイル） |
| C7 | 挙動 | ディレクトリ構成の説明が実物と合い、AI が変更箇所を見つけられるか |
| C8 | 挙動 | 守る規約（命名・禁止事項）が具体的で、違反を機械で検出できる形か |

## 計算

- 決定の点 = 決定項目の合格数 ÷ 実行できた決定項目数 × 100（未実行は分母から除き、表の下に列挙）
- 挙動の点 = 挙動項目の合計 ÷（4 × 挙動項目数）× 100
- 観点の点 = 決定の点 × 0.7 + 挙動の点 × 0.3（小数点以下切り捨て）
- 総合 = 3 観点の平均

## 依頼文の型（サブエージェントへ）

```
対象: <パス>。観点: <A 立ち上がり / B 検証ループ / C 文書の信頼性>。
目標: 下の項目を全部判定し、決定は 0/1、挙動は 0〜4 と根拠 1 行を返す。
制約: 読み取り専用。ファイルを作らない・書き換えない・install しない・外部に送らない。
      .env など秘密の値を読まない。副作用のあるコマンドは実行せず「未実行」と書く。
項目: <references/checks.md の該当節を貼る>
出力: 項目番号 / 区分 / 結果 / 根拠 1 行 の表と、最大の欠点 1 つ。10 行以内。
終了条件: 全項目に結果が付いたとき。
```
