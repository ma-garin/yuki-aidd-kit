# 相談ブリーフィングの型

advisor は会話を見ていない。**このブリーフィングだけで判断できる**ように書く。長さの目安は 40〜80 行。

```markdown
# 相談: <1 行の題>

節目: 判断前 / 詰まり / 完了前

## 1. 利用者の依頼（原文）
<利用者の言葉をそのまま。要約しない>

## 2. ここまでの経緯（時系列、箇条書き 5〜10 行）
- <やったこと> → <結果>

## 3. 証拠（原文のまま）
- コマンドと出力の末尾（エラーの全文、テストの末尾 1 行）
- 関連する差分・ファイルのパス（読んでほしい箇所に行番号）
- 秘密情報は <伏せ字> にする

## 4. 現状
- 動いているもの / 動いていないもの
- 自分の仮説（**仮説と明記**。事実と混ぜない）
- 検討して捨てた案とその理由

## 5. 制約
- 変えられないもの（環境・期限・既存規約・守る境界）

## 6. 質問（番号付き、閉じた形で 1〜3 個）
1. A か B か。自分は A に傾いている。理由は〜
2. <完了前>: 言ったのに走らせていない検証は無いか

## 7. 参照
- 会話の記録ファイルがあればパス（相談先が読めるとき）
```

## 書くときの注意

- **質問は答えられる形に**。「どう思いますか」でなく「A と B のどちらか、反対なら理由」
- **自分の傾きを書く**。隠すと、助言が追認か反論か判別できない
- 詰まりの相談では、**試したこと全部と各結果**を入れる（同じ案を勧め返されないため）
- 完了前の相談では、**受入条件と、実際に走らせた検証の末尾**を並べる
