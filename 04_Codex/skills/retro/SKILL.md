# レトロ・学びの蓄積ループ

プロジェクトの成果物ではなく「AIDDの進め方」を改善する。ここが回ると、キット自体と開発速度が継続的に上がる。

## 3層の記録（混同しない）
| ファイル | 何を記録するか |
|---|---|
| CURRENT_STATE.md | 今どこまで進んだか（進捗） |
| ADR | なぜその設計にしたか（技術判断） |
| **lessons.md** | **AIDDの進め方の知見（プロセス改善）** ← このスキルの対象 |

## トリガー
- プロジェクト完了時（必須）
- 大きくつまずいた / 手戻りが発生した時（その場で記録）
- 月1の定期レトロ（軽くてよい）

## レトロの観点（KPT変形）
- **Keep**: うまくいったAIDDのやり方（再利用したいプロンプト・フロー）
- **Problem**: 詰まった点（スキルが発火しなかった・トークンを浪費した・evalで見逃した）
- **Try**: 次に試すこと → キット（スキル/コマンド/hook）への反映候補

## lessons.md への記録形式
02_共通/ひな形/lessons.md を使う。1エントリ3-5行。冗長にしない。

## 学びを「直す場所」に結び付ける（必須）

Keep/Problem/Try を出したら、**学び 1 件ごとに具体的な編集先（ファイル）を 1 つ決める**。編集先が決まらない学びは採用しない。

1. **一回きりの出来事を除く**: その状況でしか起きない事象（特定の日のネットワーク障害・一度きりの入力ミス・個別案件の事情）は学びにしない。残す基準は「別の作業でも同じ原因で再発しうるか」。除いたものは「除外（理由）」として 1 行だけ残す
2. **編集先に対応させる**（下表。詳細は [references/lesson-to-target.md](references/lesson-to-target.md)）:

| 学びの型 | 編集先 |
|---|---|
| 守るべき規約・禁止 | `rules/*.md`（paths 付き）または `CLAUDE.md` |
| 手順・段取りの改善 | 該当スキルの `SKILL.md`（長ければ `references/`） |
| スキルが発火しなかった | 該当スキルの `description`（と `skill-triggers/*.jsonl` に発話を足す） |
| 繰り返した手作業 | `commands/*.md`（新規コマンド） |
| 機械で防げるミス | hook か検査スクリプト（`done-gate` への項目追加も可） |

3. **3 つの視点で独立にレビューし、統合者が採否を決める**（[references/review-viewpoints.md](references/review-viewpoints.md)）: 判断／発散／道具の 3 視点を別々のサブエージェントに並列で依頼 → 統合者が「採用／却下／保留」に仕分ける
4. **機械化できるものは保留に回す**: 規約文を足すより hook・検査で防げるなら、規約でなく仕組みの形で保留に載せる（「気をつける」は対策にならない）
5. **承認してから反映する**: 採用案を表で示し、利用者が選んだ分だけ編集する。スキル・規約の変更は以後の全作業に効くため、自動では書き換えない

## キットへのフィードバック（重要）
lessons.mdのProblem/Tryが溜まったら、以下に反映する:
- 発火しなかったスキル → descriptionに言い回しを追加
- 繰り返した手作業 → スラッシュコマンド化
- 繰り返したミス → hookで自動検出 or done-gateに項目追加
- 有効だったプロンプト → スキル本文に定着
- 保守者から同じ指摘を 2 回受けた → `06_保守者向け/保守者の傾向.md` に行を足し、反映先（hook / 検査 → rules → AGENTS → スキル）を決める
- 反映候補は `05_プロジェクト管理/構想.md` の価値判定基準（立ち上がり速度／トークンあたり成果／品質判定の再現性）のどれに寄与するかを 1 行で書く。書けなければ採用しない

## 出力
レトロ実行時は、Keep/Problem/Try を整理し、lessons.mdへの追記内容と、キットへの反映候補（あれば）を提示する。反映候補は「学び／編集先ファイル／変更の要点 1 行／採否（採用・却下・保留）」の表 1 つにする。除外した一回きりの出来事は表の下に 1 行ずつ。
最後に `python3 scripts/adr-to-rules.py <ADR のディレクトリ> <lessons.md> --out .claude/rules` を実行し、採用済み ADR と適用パスのある lessons の要旨を paths 付き rules（`decisions-*.md`）に書き出す（撤回した決定の出力は消える）。
続けて `python3 scripts/cite-check.py .`（書き込みなし。stale が出たら保守者が `--refresh`）を流し、ADR・rules・lessons の引用先が消えたもの（NG）・変わったもの（stale）の主張を読み直す。

## 適用範囲と引き継ぎ

**使わない場面**: 作業の途中には使わない（終了後）。単発の不具合修正だけなら使わない。
**次に渡す先**: 反映先が規約なら `rules/`、手順なら該当スキル・コマンド、機械化できるなら hook か検査へ。
