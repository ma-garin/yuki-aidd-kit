# /grill — 要件を 1 問ずつ詰める（RFD の前）

引数: $ARGUMENTS（作りたいものの一言。空なら直前の話題）

## 実行内容

作る前に、曖昧な点を**1 回に 1 問**ずつ聞いて潰す。聞き終えてから `/rfd` に渡す。

### 質問の型（守る）

- **1 回に 1 問だけ**。複数の質問を並べない
- **閉じた形**: 選択肢 2〜3 個 ＋ 推奨 1 つ ＋ 各選択肢の影響・コスト・リスクを 1 句ずつ
- 専門用語は平易な言葉に言い換える（言い換えられないときは 1 行で意味を添える）
- コードや既存文書を読めば分かることは**聞かずに読む**。聞くのは人にしか決められないこと（目的・利用者・やらないこと・期限・守る制約）
- 前の答えが次の質問を変えるなら、先に進む前に反映する

### 聞く順（木の根から）

1. 誰の・どんな困りごとを解決するか（目的）
2. 何ができたら成功か（受入条件。機械で確かめられる形）
3. やらないこと（範囲外）
4. 守る制約（環境・予算・既存資産・期限）
5. 最大のリスクと、最初に潰す方法

### 終わり方

質問が尽きた（残る未決が「実装中に分かること」だけ）ら、次の表 1 つで締める。

| 項目 | 決まったこと |
|---|---|
| 目的 | |
| 受入条件 | |
| やらないこと | |
| 制約 | |
| 未決（誰が・いつ決めるか） | |

最後に「`/rfd` に進みますか（推奨）／もう少し詰めますか」と閉じた形で聞く。

引数が空なら直前の話題を対象にする。質問に入る前に前置きを書かない。
