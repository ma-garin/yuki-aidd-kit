# 引き継ぎ（handoff）

次に作業する側（別セッションの Claude、または Codex）が**この会話を読まずに**続けられる文書を 1 本書く。

## 先に決める: 渡す相手で型が変わる

| 渡す先 | 書くもの | 型 |
|---|---|---|
| 同じ環境の別セッション | 進捗の引き継ぎ | `02_共通/ひな形/CURRENT_STATE.md` を更新する（新しい文書を作らない） |
| Codex（実装を任せる） | 作業指示書 | `02_共通/ひな形/work-order.md` の型。置き場は `docs/codex/HANDOFF_<作業名>.md` |
| 別のハーネス・別の人 | 上の 2 つの両方 | 進捗は CURRENT_STATE、依頼は work-order。この文書は両方への参照だけを持つ |

## Codex に渡すときの前提（必ず書く）

- Codex 環境は **Windows・git なし・bash なし**。コマンドは PowerShell か Python で書く。`git add`・`./scripts/*.sh` を手順に入れない
- 成果は **zip で返してもらう**。zip の中身（変更ファイル一式と `REPORT.md`）と、`REPORT.md` 先頭に書く返却時の状態を指定する
- commit・差分確認・ブランチ操作は受け取った側（Claude）が行う。Codex に頼まない
- 検証は Python で動く形にする（例 `python scripts/verify.py` の末尾 `ALL GREEN`）。bash 専用の検査は「Claude 側で実行する」と分けて書く

## 手順

1. **材料を集める**: `CURRENT_STATE.md`・直近の作業記録・未コミットの差分の有無。分からない点は推測せず「未確認」と書く
2. **重複を書かない**: 仕様・計画・ADR・issue・commit に既にある内容は**パスか URL で参照**する。写さない
3. **次の一手を 1 つに絞る**: 受け取った側が最初にやることを 1 文で。受入条件は機械で確認できる形（コマンドと期待出力）
4. **書く**（下の骨子）
5. **伏せ字**: API キー・パスワード・個人情報・絶対パス（ユーザー名を含むもの）を残さない
6. **確認**: 受け取り側がこの文書だけで「最初の 5 分」を実行できるか、1 度読み返す

## 骨子

```markdown
# 引き継ぎ: <作業名>（<日付>）

## 1. 一言で
<いま何をしていて、次に何をするか。2 行>

## 2. 状態（表）
| 項目 | 状態 | 次 |
|---|---|---|
| 完了済み | ... | |
| 未コミット・未保存 | あり/なし（パス） | |
| 検証 | <最後に流したコマンドと末尾 1 行> | |

## 3. 決まっていること（再議論しない）
- <決定と理由 1 行>

## 4. 未検証・分かっていないこと
| 項目 | 確かめ方 |
|---|---|

## 5. 次の一手と受入条件
1. <作業>（受入条件: <コマンドと期待出力>）

## 6. 受け取った側の最初の 5 分
1. <読む順。参照するパスを列挙>
2. <状態を確かめるコマンド（相手の環境で動くもの）>

## 7. 守ること・止まる条件
<work-order.md の「守ること」「止まる条件」へのリンク。作業固有の禁止だけ追記>

## 8. 呼ぶとよいスキル・コマンド
<例: `done-gate`（完了判定）、`/retro`（終了後）>

## 9. 返却方法（Codex の場合）
zip の中身 / `REPORT.md` の先頭 4 行 / 質問があれば末尾「質問」節に書いて止まる
```

## 守ること

- 長文にしない。**1 画面（約 60 行）を目安**にし、足りない詳細は参照先に任せる
- 「動くはず」と書かない。確認した事実と未確認を分ける
- 保存先は作業ディレクトリ内の 導入先の docs/codex/（Codex 向け）か `CURRENT_STATE.md`（同環境）。一時領域に置くと相手が見つけられない

## 適用範囲と引き継ぎ

**使わない場面**: 同じセッションで続けるだけのとき（`CURRENT_STATE.md` の更新で足りる）。会話の要約が欲しいだけのとき。
**次に渡す先**: 他モデルへの実装依頼の本体は `work-order.md`。完了判定は `done-gate`。終わった後の振り返りは `retro`。
