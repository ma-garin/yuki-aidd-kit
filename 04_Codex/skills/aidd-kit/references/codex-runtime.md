# 実行環境の対応と競合

この表は現在の環境で対応機能を確認するためのもの。Codex の版や接続環境を推測しない。

| Claude用の記述 | Codexでの扱い |
|---|---|
| Task・専用agent | 利用可能な委譲機能 |
| Sonnet・Opus指定 | 現在のモデル指示を優先 |
| hooksが止める | 実際の配線と能力を確認 |
| slash command | 対応するcmdスキル |
| /clear・/compact | 利用可能な会話管理機能 |
| /usage・/context | 取得できる計測だけ提示 |
| ~/.claude参照 | 配布済み原本を特定 |
| templates参照 | .claude/templatesを確認 |
| scripts参照 | 対象プロジェクトで確認 |

Claude 専用の自動 hook を Codex にあるものとしない。Git hook と共通スクリプトは別層であり、
実際にインストールされ実行される場合だけ強制力があると記録する。
kit の `00_導入/02_プロジェクト配布/install-git-hooks.sh <対象>` は配線用。
前提の `scripts/pre-commit` 等が無い場合は不足を解消してから配線する。配線失敗を成功扱いしない。

## 資料間の競合

優先されるシステム・開発者・利用者指示、対象プロジェクト AGENTS に従う。
古い記載も原文から削除せず、適用しなかった理由を証拠に残す。

- `speed-harness` の stash を使う記述より、AGENTS の stash・reset・checkoutによる巻き戻し禁止を優先する。
- 雛形の `--no-verify` による日常コミットより、Git の秘密情報・UI ゲートを迂回しない規約を優先する。
- 過去資料の「Codexにサブエージェント構造は無い」を現行環境の事実と断定しない。
- デザインの値は `02_共通/ひな形/tokens.css` の原本を使い、説明資料の例から再実装しない。
- 計測表示はコーディングを含む作業に限る最新の利用者指示を優先する。
- 工程承認欄を AI が埋めない。曖昧な承認要件は独立作業を進めながら、必要な判断だけ人間に確認する。

## 検証の報告

ISO/IEC 25010 の今回関係する品質特性と、ISTQB の重大度で根拠を確認する。
規格の全条項準拠や機能動作は、実際に検証した範囲だけを主張する。
全文機械読込、モデルの精読、構文検査、受入基準の実行テスト、実機確認、
Git への反映は異なる証拠。件数を混ぜず、未実行・判定不能を PASS に数えない。
