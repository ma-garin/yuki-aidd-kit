# AI 生成コードのレビュー観点（B42）

`qa-review-standards` の追加規則。AI が書いたコード・テストに多い欠陥の型と、指摘の書式を定める。
`references/personas.md` のペルソナ 15（テストを疑う QA リード）はこの観点を使う（本文は持たない。重複を避けるためここに寄せる）。
決定的に拾える型（未使用 import・存在しない依存の実在確認など）は自作せず、差分からの残留欠陥スキャン（B41）に任せる。

## AI 生成コード特有の欠陥

| 観点 ID | 欠陥 | 見分け方 |
|---|---|---|
| AI-01 | もっともらしい未使用コード | 呼び出し元が無い関数・分岐・引数。名前がもっともらしくレビューを素通りしやすい |
| AI-02 | 存在しない API | 型・シグネチャが実物と違う／使っているバージョンに無いメソッド。公式ドキュメントか型定義と突き合わせる |
| AI-03 | 過剰な try/except | 広い except で握りつぶし、ログも再送出も無い。原因調査を不能にする |
| AI-04 | テストの期待値をコードから逆算 | 実装の出力をそのまま assert に貼った跡（仕様書・要件と対応しない値） |
| AI-05 | コメントと実装の乖離 | コメントが説明する挙動と実装が一致しない（生成時の指示の残骸） |
| AI-06 | 依存の綴り違い | import 名・パッケージ名が実在のものと 1 文字違う（typosquat 含む） |

## テストコードのレビュー観点

| 観点 ID | 欠陥 | 見分け方 |
|---|---|---|
| AI-T1 | アサーションの弱さ | `assert result is not None` のような失敗しにくい assert しか無い。境界値・異常系を確かめていない |
| AI-T2 | 固定値のモック | モックの戻り値が常に成功値で実装の分岐を経ない。異常系・エラー経路を通していない |
| AI-T3 | フレーク要因 | 実行順・共有状態・乱数・時刻・sleep への依存。反復実行で結果が揺れないか確かめる |
| AI-T4 | 件数だけ数えるテスト | 件数・存在だけを見て中身を確かめない（`len(x) > 0` だけで値を見ない等） |
| AI-T5 | 0 件で PASS するテスト | 対象が 0 件のとき何もアサートせず素通りで成功する（データが無くても壊れているとわからない） |

対象・条件・期待・実際・再現方法がテストコードから読み取れるかを見る。読み取れなければそれ自体を指摘する。

## 指摘の型

指摘は 1 行 `file:line／観点ID／根拠／直し方` で書く。根拠は実測（該当行の引用・実行結果）のみで推測を書かない。
複数の観点にまたがる指摘は主たる観点 1 つに寄せ、同じ箇所を重複して出さない。
