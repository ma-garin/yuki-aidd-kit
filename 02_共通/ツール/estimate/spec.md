# 予実管理ロジック仕様 v12（運用手順は est.py の docstring が正）（Claude の作業見積）

## 0. 目的・評価基準
- 対象: 応答1行目「見積: N分（HH:MM 完了予定）」と、完了報告の最終行「見積: N分 / 実測: M分（T0→T1、待ち除外S秒）/ CP往復: X→Y」。表示形式の枠は変えない。
- 合格判定（1件ごと、初回見積で判定）: 実測5分以上は 比=実測/見積 が 0.67〜1.5。実測5分未満は |実測−見積| ≤ 1分。
- 系統判定（集計）: T0/T1 の生値がある直近10件（実測の長さを問わない）で、Σ実測/Σ初回見積 が 0.9〜1.1 かつ未完率が20%以下。過大・過小はどちらも違反。
- Claude は時計を持たない。時刻は date の出力だけを使う。体感・暗算・「約」付きの値は記録にも報告にも使わない。
- 時刻計算（経過・実測・完了予定・比・合否）はすべて est.py（UNIX秒で計算。t0/plan/reest/now/ext-begin/ext-end/pause/resume/end/abort）で行い、Claude は出力値を転記するだけにする。日付をまたいでも壊れない。

## 1. 用語
- T0: 作業を始める応答で最初に呼ぶツール呼び出しに含めた `date +%H:%M:%S` の出力。
- T1: 完了報告の直前に呼ぶ `date` の出力。
- 待ち: ターン間のユーザー返答待ちは pause/resume で除外する。ターン内の承認待ちは Claude から区別できないため実測に含め、往復間隔が閾値を超えた件は long_gap_s に記録して往復単価の算出から除外する（est.py tick）。
- 実測: 各ターンの (T1−T0−待ち) の合計（秒）。ターン間のユーザー返答待ちは自動的に含まれない。
- CP往復: クリティカルパス上のツール呼び出し往復数。同時に投げた呼び出しは1と数える。
- 種別: 調査 / コード+CI / UI新規 / UI改修 / ブラウザ操作 / 外部投稿 / 文書・回答。
- 往復単価: 種別ごとの「(実測 − 外部待ち) / 実際のCP往復数」の中央値（秒/往復）。各往復の生成・読込・思考時間を含む。分母に予定往復数は使わない（往復数のずれと単価のずれを二重に数えないため）。
- 外部待ち: CI・集計ジョブ・サブエージェントなど、Claude の外で進む処理の待ち時間。起動時と完了検知時の date 差で記録する。その間のポーリング呼び出しは、予定CP往復Xにも実際のCP往復にも数えない。
- 報告生成時間: T1 から最終応答の送信までの時間。計測できないため、固定値20秒を使い、完了予定時刻の計算にだけ加える。成果物そのもの（文書・回答本文・コード）は T1 より前にファイルへ書き出すことを必須とし、最終応答では生成しない。ファイル化できない短い回答のみの作業は、見積に「予定文字数 ÷ 生成速度（初期値 1,000字/分、暫定）」を加える。

## 1.5 運用手順（est.py）
- 新規依頼: 最初のツール呼び出しで `est.py t0`（実行可能性確認と同梱）→ `est.py plan <種別> <X> [外部待ち秒]` の出力を見積行に転記。
- クリティカルパス上の各ツール呼び出しに `est.py tick` を同梱する（往復数・承認待ちの自動判定・70%判定）。
- CI・委譲: `ext-begin` / `ext-end`。ターン末: `pause`、次ターン最初: `resume`。t0 は新規依頼のときだけ。
- 週次の振り返り: `est.py weekly [日数]` で範囲外の件を種別ごとに洗い出し、原因の工程を lessons に書く。
- 完了: `est.py end`、未完: `est.py abort`。出力の T0・T1・待ち・実測・往復・比・合否を完了報告に転記する。
- 見積秒・往復単価・往復数補正・系統判定は est.py が計算する（stats）。Claude は計算しない。

## 2. 見積の出し方（1応答の中で完結）
1. 見積行を書く前に、1回のツール呼び出しで `est.py t0` と実行可能性確認（権限・認証・どのブラウザか・対象の状態）をまとめて行う。確認できない要素は名前を挙げて保持する。
2. 作業を工程に分け、予定CP往復数 X を数える（必須でログに記録）。X には計測用の固定往復も必ず含める: T0確認の呼び出し1、plan の呼び出し1（T0確認と同時に投げられないため）、T1の date 1（最後の作業呼び出しと同時に投げられる場合は0）、複数ターンになる場合は各ターンの T0/T1。
3. 素の見積 = X × 往復単価（種別） ＋ 外部待ち（CI・集計ジョブ等。並行分は最長のみ。実測値がある待ちだけ）。
4. 往復単価の決め方: T0/T1 の生値がある該当種別の件が3件以上ならその中央値。3件未満なら種別ごとの初期値を使う（初期値が暫定のものは、そう明記した値）。初期値（2026-10-31〜11-01 の概算実績から算出、付録参照）:
   - UI改修: 24秒/往復（付録 #8〜#10 の中央値）
   - コード+CI: 17秒/往復（付録 #2 の1件のみ。暫定）
   - UI新規: 24秒/往復（UI改修の値を流用。暫定）
   - 調査・文書・回答: 23秒/往復（暫定。自種別の実測が3件そろったら置き換える）
   - ブラウザ操作: 27秒/往復（#4 の概算）
   - 外部投稿: 30秒/往復（#3 の概算）
   - 外部待ちの初期値: CI（テスト）2分、集計ジョブ 3分、サブエージェント（レビュー等の単発委譲）50秒/回（本日のレビュー委譲6回の実測 37〜63秒の中央値）。委譲を含む作業では必ず見積に加える。実測が得られたら置き換える。
5. 往復単価はすでに実測由来なので、往復単価には補正係数を掛けない。一方、予定CP往復数Xは見積時の予測なので、種別ごとの「実際のCP往復 / 予定X」の中央値（往復数補正、3件以上たまったら適用）をXに掛ける。
6. 余裕は、手順1で名前を挙げた未確定要素が過去に実際に失敗した種類の場合だけ付ける。上限は素の見積の25%と5分の小さい方。丸め上げ・一律上乗せは禁止。
7. 見積は秒で算出してログに記録し、比・合否・系統判定はこの秒の値で行う。表示だけを分単位に四捨五入し、1分未満は「1分」と表示する。完了予定時刻 = T0 ＋ 見積秒 ＋ 報告生成時間20秒（est.py plan が出力）。

## 3. 進捗の監視と再見積
- CP上のツール呼び出しには毎回 date を同時に含める。そのたびに「経過 = 現在 − T0 − 待ち」を計算する。
- 再見積は1回だけ。条件は (a) 調査結果で前提が崩れ、予定CP往復数が変わった、または (b) 経過が見積の70%に達した、のどちらか。さらに、残りの往復数×往復単価で超過、または見積の半分以下で終わる見込みのときに限る。
- 再見積も §2 と同じ式で出す。合否判定は初回見積で行い、再見積はログに残す。

## 3.5 中間報告
- 工程が1つ終わるたび（ループ作業では1周ごと）、または経過が見積の50%に達した時点の、早い方で中間報告を出す。サブエージェントやCIなど外部待ちに入る直前も必ず出す。
- 形式は「項目／状態／次」の表1つと、「見積 N分に対し経過 M分（date 取得値）」の1行。中間報告を出さずに次の工程へ進むことは違反とし、§5 の自己検査の対象にする。

## 4. ユーザー操作を含む作業
- ユーザーの操作が要る工程は見積の対象外とし、見積行を出す応答の中で対象外であることを1文で書く。
- 作業が未完で終わった場合は未完フラグを立てる。未完の件は比・合否・Σ実測/Σ見積から除外し、未完率と往復単価（中断までの実測 ÷ 中断までの実際のCP往復）にだけ使う。

## 5. 違反の自己検査（完了報告の前に毎回）
- T0・T1・待ちの生値が報告に書かれているか。
- 工程ごとの中間報告を出したか（§3.5）。
- 完了報告の本文に「種別・外部待ち秒・実際のCP往復・予定X」を書いたか（最終行の枠は変えない。セッションをまたいだ会話検索で種別別の集計を可能にするため）。
- 合否判定の結果と、範囲外ならずれた工程（往復数のずれか、往復単価のずれか、外部待ちのずれか）を1行書いたか。
- 1つでも欠けていれば、その報告は違反としてログに記録する。

## 6. 予実ログと統計
- 1件ごとの記録: 依頼内容、種別、予定CP往復数、使った往復単価、外部待ちの見積、初回見積、再見積、T0、T1、待ち、実測秒、実際のCP往復数、比、合否、未完フラグ、ずれ要因。
- 統計対象: T0/T1 の生値がある全件（往復単価の算出と系統判定の両方に使う）。概算実績（付録）は初期値の根拠にだけ使い、統計対象にしない。
- ログは est.py end/abort が書く。Claude が直接 log.csv に書き込むことは禁止する。
- 保存先: セッション中は作業環境のファイル。セッションをまたぐ保存は yuki-aidd-kit リポジトリ（ユーザーの承認後に作成）。
- ログを読めない環境では、見積の前に過去の会話から完了報告（最終行の見積・T0→T1・待ち・CP往復と、本文の種別・外部待ち秒・予定X）を検索して集め、往復単価を算出し直す。それも得られない場合は初期値を使い、§5 の自己検査で代替する。
