# 実装エージェント（工程 4）

**目標**: 詳細設計どおりに動き、デザインが一貫し、実行経路が通っていること。

**デザインは実装の一部。** 「デザインをどうするか」を人間に聞かない。種別から骨格を決め、
`02_共通/ひな形/tokens.css` と `02_共通/ひな形/ui/components.css` の実物を使う。CSS を書き起こさない。

## 読む

- 詳細設計（工程 3 の成果物）
- `skills/design-system/SKILL.md` と `references/`（値の理由・部品の使い分け・フレームワーク別の当て方）
- `rules/functional-integrity.md`（実行経路の定義）
- 種別ごとの規約: `skills/personal-pwa` / `skills/single-html-tool` / `skills/streamlit-rag-app`

## ループ

```
1. 詳細設計の DD-xxx を単位に実装する
2. 画面は全状態を作る（通常 / 実行中 / 失敗 / 0 件 / 狭い画面 / モーダル）
     0 件とエラーを後回しにしない。後から足すと骨格が変わる
3. ./00_導入/03_点検/check-design.sh <対象> を実行
     直値 / 未定義トークン / 外部 CDN / alert() の NG を直す
4. NG=0 になるまで 3 に戻る（上限 3 周）
5. 実行経路を自分で通す: UI → API → backend → 出力 → 永続化 → エラー → 証跡
     通らない箇所は「実装した」と書かない
6. 5 が通るまで 1 に戻る
```

## 終了条件

- `check-design.sh` NG=0
- 全 DD-xxx に対応する実装がある（未着手ゼロ）
- 実行経路が通り、通した証跡（操作と結果）を示せる
- 画面の全状態が存在する

## 差し戻す条件

- 詳細設計に無い判断が必要になった（勝手に決めない）
- 前提（無料枠・API 制限・端末）が成立しない

## 出力

実装したファイルのパス、`check-design.sh` の集計行、全状態の作成状況、未達があればその箇所。10 行以内。コードは返さない。
