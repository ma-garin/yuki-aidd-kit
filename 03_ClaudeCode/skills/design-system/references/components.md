# 部品の使い分けと落とし穴

CSS 本体は `02_共通/ひな形/ui/components.css`（クラス名をそのまま使う。ここに CSS を複製しない）。
このファイルは「いつどれを使うか」と、**実際の不具合から来た実装時の注意**。実例は `02_共通/ひな形/components/demo.html`。

## ボタン `.btn` `.btn--primary` `.btn--ghost` `.btn--danger`

- 塗り（`--primary`）は **1 画面に 1 つ**。それ以外は白地＋ボーダー（`.btn`）かテキストボタン（`.btn--ghost`）
- ラベルは動作名（「保存する」「削除する」）。「はい／いいえ」「OK」「次へ」を使わない
- 破壊的操作は `.btn--danger`（枠）か `.btn--danger.btn--primary`（塗り。確認ダイアログの実行ボタン）
- 処理中は `aria-busy="true"` ＋ ラベルを「処理中…」に。`disabled` にしない（フォーム値が送信されない。二重送信対策にならない）
- アイコン付きは `<span data-icon="save" data-icon-size="16"></span>` を先頭に

## 入力 `.input` `.select` `.textarea` `.field` `.field-err-text` `.banner-err`

- `.field` で ラベル → 入力 → エラー文 を縦に積む。ラベルは上（横並びにすると狭幅で崩れる）
- **エラーは 2 段構え**: フォーム全体の要約は上部の `.banner-err`（「ログインできませんでした」）、個別項目は該当フィールド直下の `.field-err-text`（「パスワードが正しくありません」）。片方だけに頼らない
- エラー色は Critical のみ。警告と混同して High（橙）を使わない
- `alert()` やブラウザ標準のバリデーションポップアップは使わない（モーダル・バナー・フィールド直下のいずれかで表現する）
- プレースホルダは例示であって説明ではない。必須の説明はラベルか補足文に

## バッジ `.badge .badge-{critical,high,medium,low,info,new}`

- severity の表現はピル型バッジで統一。文字色＋淡い背景＋同系ボーダーの 3 点セット
- コードでは severity を**列挙**（critical / high / medium / low / info）として扱い、色名を props や引数に出さない
- `.badge-new` はプライマリ淡背景。状態色を装飾（見出しを赤にする等）に転用しない

## カード `.card` `.card-grid` / スコア `.score-card` / KPI `.kpi`

- 1 カード = 1 対象。カード内は「タイトル → 要約 1〜2 行 → バッジ列 → アクション」の縦順
- `.card-grid` は最小幅 300px で折り返し。360px では 1 列（`layout.css` のブレークポイント）
- `.score-fill` は `display:block`。`span` で塗ると寸法が無視されて棒が出ない
- KPI は「ラベル小文字グレー → 等幅の大きな数値 → 前回比を小さく」。良し悪しは `.kpi-delta.up/.down` の色だけで表し、カードに背景色を塗らない
- 説明が要る指標には情報ツールチップ（下記）を添える。全部に付けない

## 表 `.table` `.table-wrap` `.col-filter-btn` `.col-pop` `.pagebar` `.pager`

- 罫線は横線のみ（縦線は引かない）。ヘッダ行は薄グレー地＋太字。数値列は `.num`（右揃え＋等幅）
- 一覧の絞り込みは「全体トップの検索・並び替え」と「列ごとのフィルタ（列見出しのアイコン → `.col-pop`）」を分けて共存させる。両方を 1 つの UI に混在させない
- 表示件数は可変（5 / 10 / 30 / 50 / 100 / すべて）。**件数変更でページは 1 に戻す**。フッターに `1–10 / 48 件` のように現在範囲／総数を併記
- 狭幅は `.table-wrap` で横スクロール（列を無理に折り返さない）
- 読み込み中は `.skeleton` の行を出す（空の表を一瞬見せない）

## トグル `.toggle` / セグメント `.seg`

- 2 値の ON/OFF はトグル、3 値以上の相互排他（テーマ: ライト／ダーク／システム等）はセグメント。ラジオボタンの素朴な並びは使わない
- トグルは `role="switch" aria-checked` を付ける。つまみの色は `--color-knob`（ダークで白飛びしない）

## 情報ツールチップ `.info-ic` `.tooltip` `.edge-left` `.edge-right`

- 用語・集計ロジックなど「本当に説明が要る項目」だけに付ける。装飾目的で乱用しない
- **ホバー（と `:focus-visible` / `.open`）でのみ表示**。常時表示にすると下の行のクリックを妨げた（実不具合）
- 既定は中央揃え（`translateX(-50%)`）。**サイドバー内など画面左端では吹き出しが画面外にはみ出して文字が切れる**（Harness ToDo モックで実際に発生）→ `.edge-left`。右端では `.edge-right`。配置場所ごとに付け分けるか、クランプ判定を入れる
- 濃色チップは両テーマ固定（`--color-tooltip-bg/-text`）。2〜3 行で収める

## モーダル `.modal-backdrop` `.modal` `.modal.sm` `.modal-head/-body/-foot` `.modal-close`

- **開閉 3 経路**を必ず用意する: 開くボタン／`.modal-close`（ヘッダの × とフッターのキャンセル）／backdrop 自身のクリック（`e.target === backdrop` で判定し、中身のクリックまで拾わない）
- 同時に開くモーダルは 1 つ。ページ内に複数の `.modal-backdrop` を置いてもよいが開閉関数は共通化する
- 確認ダイアログは `.modal.sm`。**破壊的操作は対象名を本文に動的に埋める**（「〇〇を削除しますか」と一般化しない）。実行ボタンは `.btn--danger.btn--primary`、アイコンは Critical 色（円形背景 `--color-critical-bg`）
- 単純な確認は `Feedback.confirm()`（`<dialog>` ベース。`Promise<boolean>`）で足りる。フォームを持つときだけ `.modal` を組む
- `.modal-head .modal-close` だけがアイコンボタンの見た目になる。フッターの `.btn.modal-close` はボタンの見た目のまま（セレクタを広げると壊れる）

## 通知／リッチポップオーバー `.notif-pop` `.notif-item.unread`

- テキストだけの軽量ポップオーバー（ツールチップ・列フィルタ）と違い、リストや複数行を持つ場合はこちら
- **画面右上のヘッダーアイコンから開くものは右揃え**（`right:0`）。中央揃えは画面外にはみ出す（ツールチップの節と同じ理由）
- 開閉は「トリガークリックでトグル」＋「ドキュメント全体のクリックで閉じる」。ポップオーバー内部のクリックは `stopPropagation()` で外側判定に伝播させない
- 未読／既読は背景の濃淡だけで区別。バッジを乱用しない

## 空状態 `.empty-state`（静的）／ `Feedback.emptyState()`（JS）

- 用途は 2 種で**文言とボタンを変える**: ①フィルタ・検索の結果 0 件（「条件に一致するタスクがありません」→ 解決は「フィルタを解除する」）②新規ユーザーでデータ未作成（「まだ〇〇がありません」→ 解決は「最初の〇〇を作成する」）。どちらも同じ空のグレーアイコンで済ませない
- 枠だけ残さない。次にできることを 1 文とボタンで示す
- クラス名は静的マークアップと `feedback.js` で同じ（`.empty-state` `.empty-state-title` …）。併用しても競合しない

## コールアウト `.callout .callout--{critical,high,info,low}`

- 本文内のエラー・注意。左に色帯。`alert()` の代わりに本文の該当位置へ置く
- Critical はエラー、High は警告、Info は補足、Low は成功の余韻。混同しない

## スケルトン `.skeleton`

- 読み込み中の表の行・カードの見出しに。高さは 1em、幅は `style="width:40%"` のように内容に合わせる
- スピナーは「操作の結果を待つ」ときだけ（`Feedback.busy`）。画面の初期表示はスケルトン

## レスポンシブ（`layout.css`）

- 検証幅は 360×820 / 768 / 1366×768 / 1920×1080。1366 以下でサイドバー 200px、768 以下で off-canvas（`.sidebar.open`）、360 でカード・KPI 1 列
- グローバルバーは高さ固定なので**折り返さない**（`white-space: nowrap`。狭幅ではラベルを隠しアイコンだけにする）
- トップバーは `min-height` にする（パンくず＋見出しの 2 行が 56px を超えて重なった実不具合）
