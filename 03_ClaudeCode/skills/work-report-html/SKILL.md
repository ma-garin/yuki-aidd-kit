# 作業レポート（HTML・図とスクリーンショットつき）

読み手は「その場にいなかった本人」。会話を読まなくても、何ができるようになり、どう確かめ、何が残っているかが 1 ページで分かることを目標にする。

## 1. 範囲を決める（最初に 1 回）
- 依頼の言葉に範囲があればそれに絞る（例: 「Cloudflare でやったこと」→ 公開作業だけ。アプリの改修は入れない）。
- 範囲が書かれていなければ「このセッションで行ったこと」。迷ったら狭い方。

## 2. 材料を集める（推測で埋めない）
| 材料 | 取り方 |
|---|---|
| 時刻つきの作業記録 | 会話の計測行・コマンド出力。やめた作業・撤去したものも書く |
| 変更の一覧 | `git log --oneline origin/main` と PR 番号 |
| 設定値 | 実際の画面・コマンド出力から写す。記憶で書かない |
| 確認結果 | HTTP ステータス・件数・テスト集計など実測値。未実施は「未確認」 |

## 3. スクリーンショットは実物を撮り、本文と照合する
- 公開 URL・ローカル画面: Playwright のヘッドレスで撮る（スマホ幅 390px、`device_scale_factor=2`）。ログイン前の画面も撮れる。
- 管理画面（ログインが要るもの）: Claude in Chrome で開き `save_to_disk: true` で保存。読み込み中の画面を撮らないよう、表示を確かめてから撮る。
- 既に検証で撮った画像があれば再利用する。
- **撮った画像は必ず Read で見て、本文の説明と食い違いが無いか照合する。**（2026-10-12: ログイン画面を撮って、「メールのコードでログイン」という説明の誤りが見つかった。食い違いを見つけたら報告書だけでなく README 等の元の記述も直す）
- 画像はページと同じフォルダの `img/` に置き、公開時に `files` で一緒に送る。

## 4. 構成（assets/template.html の順）
1. 結論（何が届いたか・確認済みか）＋初出の用語を 2 文以内で
2. 構成図: mermaid `flowchart`（採らなかった経路は点線と理由）
3. 流れの図: mermaid `sequenceDiagram`（利用者の操作から結果まで）
4. 画面: スクリーンショットとキャプション（何を見ればよいか）
5. 行ったことの記録: 時刻・作業・結果の表
6. 設定内容: `dl`
7. 確認の結果: 実測値の表
8. これからの使い方: 更新・追加・取り消しの手順
9. 注意と残り: 未確認・リスク・運用上の注意

項目が無い節は削る。空の節を残さない。

## 5. 書き方
- 利用者の言葉で書く。関数名・内部パスは手順に必要なときだけ `code` で。
- 断定は確かめたことだけ。確かめていないことは「未確認」と書き、確かめ方を添える。
- 秘密情報（パスワード・トークン・鍵・合言葉）は書かない。本人のメールアドレスは非公開ページに限り可。
- 見た目は `assets/template.html` の CSS をそのまま使う（ライト・ダーク両対応、390px で横スクロールなし）。

## 6. 公開
1. `Artifact` の `action: "quickstart"`（`intent: "other"`）を先に呼ぶ（初回のみ）。
2. テンプレートを scratchpad にコピーして埋め、`Artifact` で `file_path` と `files: {"img/x.png": "<path>"}` を渡して公開する。
3. 直しは同じ `file_path` に Edit → 同じ応答で再公開（URL が変わらない）。Bash で書き換えたファイルは Write の前に Read が要る。
4. mermaid はページ表示時に描かれる。描画を確かめていないときは報告でそう書く。

## 7. 報告
URL と、ページの節の並びを 1〜3 行で。図の描画が未確認ならそれも 1 行。
